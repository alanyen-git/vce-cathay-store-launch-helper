# VCE 國泰開店小幫手｜雲端資產管理

手機優先的開店固定資產建檔工具，為「開店小幫手」的 VCE 國泰品牌版本。資料以公司為範圍管理門市、開店專案、資產與照片；部署在受保護的 ChatGPT Sites 環境，使用 D1 儲存結構化資料、R2 儲存照片。

## 目前可用

- 公司內唯一的資產編號與多門市／多專案基礎資料
- 固定資產正式建檔：必填照片、分類、用途、名稱、價格、採購單位與廠商
- 受伺服器保護的照片存取與角色邊界
- 請求冪等：行動網路重送同一筆建檔不會重複新增
- 資產、照片認領、稽核紀錄以單一 D1 batch 寫入
- JPEG／PNG／WebP 照片驗證；前端重編碼移除定位等中繼資料
- 取消建檔即清除暫存照片；同一使用者逾期暫存會於後續操作時清理
- 舊版本機資料可逐筆匯入，失敗資料保留在本機並顯示原因

## 角色

| 角色 | 可建立資產 | 可建門市／專案 | 可保留匯入編號與狀態 |
| --- | --- | --- | --- |
| 系統管理者 | 是 | 是 | 是 |
| 專案主管 | 是 | 是 | 是 |
| 建檔人員 | 是 | 否 | 否 |
| 檢視者 | 否 | 否 | 否 |

站點存取名單與應用程式內角色是兩層不同權限：必須先由 Sites 存取政策允許訪問，再由公司成員角色授權操作。

## 開發與驗證

```bash
npm run db:generate
npm run lint
npm run build
```

資料模型更新後，必須新增新的 Drizzle migration；**不可修改已發布的 migration**。Sites 發布時會先套用 D1 migration，再部署 Worker。

## 資料與安全規則

- 不接受 SVG、GIF 或僅偽裝成圖片的檔案；伺服器會比對檔案格式特徵。
- 暫存照片僅能由上傳者完成建檔；一張照片只能認領到一筆資產。
- 資產編號不可由一般建檔人員指定；舊資料保留編號僅限管理者。
- 不得從 D1 或 R2 直接刪除正式資產資料。日後應以狀態轉換、理由與稽核紀錄處理報廢、遺失或封存。
